# .chirpkey 离线身份恢复文件规范（v1）

iOS、macOS、Windows 和 Android 使用同一格式备份 Ed25519 账号根身份。文件和原密码足以在本机离线解密。用它登记新设备时，用户仍须在原服务通过 Passkey 认证，客户端再核对账号及根公钥。设备私钥、Passkey、登录令牌、好友信任记录、MLS 会话秘密、聊天记录和附件密钥均在备份范围之外。

## 文件名与识别

导出扩展名为 **`.chirpkey`**，文件前 8 字节为 ASCII **`CHIRPKEY`**。Apple 系统文件类型标识为 `cn.youzifeile.chirp.chirpkey`。四端按文件内容验证格式，一律拒绝带有旧文件头 `CHRIPKEY` 的导出。将旧文件从 `.chripkey` 改名为 `.chirpkey` 仍会被拒绝，直接改写文件头则会使认证标签失效。

建议文件名为 `<用户名>_<YYYY-MM-DD>_<来源平台>.chirpkey`，例如 `alice_2026-11-21_iOS.chirpkey`。日期取导出设备的本地日历日期。替换用户名中的非法文件名字符，重名时通过系统另存为确认或追加序号。默认文件名会透露用户名、日期和平台，允许用户自定名称。Windows 文件选择器按 `.chirpkey` 筛选，身份匹配只使用经过认证的载荷和当前登录授权。

## 密码与本地秘密

- 密码至少含 **16 个 Unicode 标量值**，UTF-8 编码最多 **1024 字节**。创建时输入两次，按 UTF-8 字节比较。保留大小写、首尾空白和原始 Unicode 表示，加密与解密采用相同规则。
- 输入框支持粘贴和密码管理器。持有文件的人可以离线反复尝试密码，创建时应提示用户选择足够随机的长密码。管理员无法找回密码。一份有效备份的所有副本都可由原密码解密，重新加密另一个副本无法撤销已经泄露的根密钥。
- 密码、派生密钥和根种子仅在本次操作的内存中使用，完成或失败后尽快释放。禁止将其写入日志、崩溃附件、分析事件、剪贴板或日常设备密钥库。内存清理无法保证擦除系统或第三方创建的所有副本。
- 首次设置期间，应用只在私有存储中暂存恢复密文和续办所需的状态，并排除自动云备份、同步和上传。用户自行选择外部保存位置。服务端只接收公开身份材料和持钥证明。

## 二进制布局

文件依次存放 54 字节头、`N` 字节密文和 16 字节 GCM 认证标签。下表偏移从 0 开始，所有整数均为无符号大端序。磁盘上存放原始字节。

| 起始偏移 | 字节数 | 字段 | v1 编码或取值 |
| ---: | ---: | --- | --- |
| 0 | 8 | 格式标识 | `CHIRPKEY`，十六进制 `43 48 49 52 50 4B 45 59` |
| 8 | 2 | 容器版本 | `1` |
| 10 | 2 | 加密套件 | `1`，Argon2id 与 AES-256-GCM |
| 12 | 4 | Argon2id 内存 | `65536` KiB（64 MiB） |
| 16 | 4 | Argon2id 迭代次数 | `3` |
| 20 | 2 | Argon2id 并行度 | `4` |
| 22 | 16 | 盐（salt） | 每次加密使用系统安全随机源生成 |
| 38 | 12 | GCM nonce | 每次加密独立随机生成，同一密钥下禁止复用 |
| 50 | 4 | 密文正文长度 `N` | `1 ≤ N ≤ 65536`，与明文的 UTF-8 字节数相同 |
| 54 | `N` | 密文 | 加密后的 UTF-8 JSON |
| `54 + N` | 16 | 认证标签 | 紧跟密文，标签结束即为文件末尾 |

Argon2id 使用版本 `0x13`，以原始密码字节和头内的盐派生 32 字节 AES 密钥。AES-256-GCM 使用头内的 nonce，并将**从磁盘读出的完整 54 字节头**作为附加认证数据（AAD）。文件总长必须严格等于 `54 + N + 16`，范围为 71 至 65606 字节。算法背景见 [RFC 9106 参数选择](https://www.rfc-editor.org/rfc/rfc9106.html#section-4) 和 [OWASP 认证加密说明](https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html#cipher-modes)。

## 加密载荷

明文为一个 UTF-8 JSON 对象，恰好包含以下十个必填字段。字段顺序可以不同。读取端必须拒绝重复键、未知键、缺少字段、类型错误和无效值。下表字符串长度均按 UTF-8 字节计算。

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `payload_version` | 整数 | 固定为 `1` |
| `identity_protocol` | 字符串 | `chirp-mls-authenticated-v5`。身份协议与容器分别校验版本 |
| `root_algorithm` | 字符串 | `Ed25519` |
| `root_seed` | 字符串 | 32 字节账号根种子，使用标准带填充 Base64 |
| `root_public_key` | 字符串 | 32 字节 Ed25519 根公钥，使用相同 Base64 编码。必须与种子推导出的公钥一致 |
| `service_origin` | 字符串 | 规范化的 HTTP 或 HTTPS origin，最长 2048 字节。例如 `https://fixture.test:443`。小写主机后显式写出有效端口（HTTP 默认 80，HTTPS 默认 443），省略用户信息、路径、尾部斜杠、查询和片段 |
| `account_id` | 字符串 | 服务端不可变账号 ID，1 至 128 字节 |
| `username` | 字符串 | 导出时用户名，最多 320 字节，仅供辨认。恢复时用 `account_id` 和根公钥匹配账号 |
| `created_at` | 字符串 | 加密生成时间，UTC RFC 3339，以 `Z` 结尾，可含小数秒，最多 64 字节 |
| `source_platform` | 字符串 | `iOS`、`macOS`、`Windows`、`Android` 四者之一。每端均接受四种来源 |

## 导出与恢复

1. **创建和保存。** 在客户端用安全随机源生成账号根，独立生成设备密钥。加密后用同一密码完整解密自检，逐字节比较原始 JSON，再可靠保存候选设备与内部密文。同一次首次设置重复导出时，保存同一份密文字节。
2. **确认。** 系统报告导出成功后，用户在前台确认页累计等待五秒并主动确认。可重新选择实际保存的文件，用密码核验根公钥。确认状态绑定账号、根公钥及文件摘要。首次绑定成功并核对服务端响应后，移除内部待办密文。
3. **读取。** 先限制输入大小，检查格式标识、版本、套件、固定参数、`N` 和实际总长。任何不符立即拒绝，包括截断或尾随字节。通过后再执行 Argon2id 并验证 GCM 标签，认证成功才解析 JSON。密码错误和标签错误统一作为解锁失败处理。
4. **恢复和登记。** 从根种子重新推导公钥，与文件公钥、当前已认证服务的 origin、不可变账号 ID 及服务端已有根绑定逐项核对。新设备独立生成设备密钥，由原账号根签发证书，并联网完成持钥证明及资格检查。任何步骤失败均保留已有有效身份和用户文件。[登录、续办与恢复](identity-and-friends/README.md#注册首次登录与加密离线恢复)

## 跨平台验证

共享公开向量 `recovery-v1.json` 中的 `file` 采用 Base64 包装，解码后是 453 字节的完整文件，`N = 383`。使用 `password` 原样解密后，结果必须与 `payload` 的 UTF-8 字节完全相同。`retired_file` 是使用相同密码的真实旧格式测试样本，必须被拒绝。样本密码、根种子及随机参数全部公开，仅用于测试。[共享测试向量](../internal/identity/testdata/recovery-v1.json) · [Go 向量生成器](../scripts/identity-vectors/main.go) · [Apple 原生桥接测试](../Client/apple/MLS/Tests/ChirpMLSTests/RecoveryVectorTests.swift)
